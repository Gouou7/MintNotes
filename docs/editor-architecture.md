# 编辑器架构原则

[返回项目说明](../README.md) · [系统设计](system-design.md) · [开发与验证](../README.md#本地开发)

本文记录编辑器（即与文档的编辑和显示相关部分）已采纳的行为规范与验收要求。普通修复遵循现有规范；确需改变或补充规范时先获得用户许可，不因实现变化自动改写原则。具体版本变化记录在[变更日志](../CHANGELOG.md)。

## 一、编辑器模式

编辑器提供三种模式：

- **实时模式**：编辑 Markdown，同时显示排版效果。
- **源码模式**：显示并编辑完整的 Markdown 源码。
- **阅读模式**：只显示渲染结果，不能编辑。

三种模式共享同一份源码。编辑、保存、历史、同步和导出均以源码为准；解析树、DOM 和渲染结果不得反过来改写正文。源码正确性、编辑准确性和撤销完整性优先于渲染效果与交互便利。

> “源码”是用户实际输入和保存的原始文本，包含内容正文和控制格式的 Markdown 标记；
> “渲染”是根据源码生成的显示效果。

## 二、实时模式的显示规则

实时模式应忠实呈现源码，将合法 Markdown 标记范围内的正文展示为对应样式。

- 单个源码换行也按两行显示；源码中的空行应按实际数量显示，后续输入不得将原有换行改为空格。
- 实时、阅读与大纲对语法的识别规则应一致。Setext 标题下划线至少包含三个连续同类 `=` 或 `-`，末尾可带空格或 Tab；代码围栏延续到匹配的结束标记，未闭合时延续到文档末尾。
- Front Matter 的嵌套 YAML、多行值、锚点与别名在源码模式编辑；无效语法保持源码，不静默改写。

### 编辑态与渲染态

实时模式中的内容具有两种显示状态：

- **渲染态**：隐藏部分 Markdown 标记，显示对应的排版效果。
- **编辑态**：编辑时，临时显示部分区域 Markdown 标记，以方便格式修改。

> Markdown 标记本身也是源码的一部分，隐藏只影响显示。
> 两者只是显示状态不同，不是两份独立内容。
> 编辑态显示的 Markdown 标记为次要内容，应显示为较弱颜色（如灰色）。

### 两态切换时机

**语法编辑单元**：定义当光标移动到某一个格式中，文档中应显示为编辑态的范围。

不同格式对应的语法编辑单元不同：

| 语法 | 编辑单元 |
| --- | --- |
| 正文 | 正文的渲染态和编辑态相同，不涉及切换 |
| 标题、列表 | 通常为当前源码行，不以视觉自动换行为界 |
| 粗体、斜体、删除线、高亮、链接、行内代码、行内公式 | 完整的行内语法结构 |
| 围栏代码、块级公式、Callout | 完整的语法块 |
| 普通引用 | 未被普通空行隔开的完整引用块；只有 `>` 的空引用行仍属于该块 |
| 图片、表格、Mermaid、其他嵌入内容 | 按下文详述的特殊规则 |

- 光标位于普通文本语法编辑单元内部或起止边界时，该单元进入编辑态；没有光标、选区端点或专用编辑状态激活的单元恢复渲染态。鼠标和键盘操作光标时遵循相同的激活规则。
- 选区区域中的单元和选区两端所在单元全部进入编辑态；鼠标拖选期间暂缓切换，松开后统一展开，避免干扰选择。

### 两态切换规则

一般规则：

- 嵌套语法应显示完成当前编辑所需的内层源码和外层标记。
- 尽量避免两态切换时的视觉：
    - 标题、粗体、链接等内容进入编辑态后，应尽量保留正文的字号、行高和排版，只以较弱但清晰可辨的颜色显示格式标记。
    - 列表、引用进入编辑态时，源码从统一正文左边距开始，仅保留源码中的实际空格与 Tab 缩进，不叠加渲染容器缩进，也不将标记挤入左侧留白。
    - 标记展开可能引起换行，应优先保持光标附近的视口稳定，不要求整页布局完全不变。
- Markdown 标记与正文使用相同字体并自然占位；ATX 标题标记随标题字号，Setext 下划线标记按正文字号。

特殊或补充规则：

- **代码块、公式**：可以切换为源码编辑，并尽量减少展开与收起造成的页面跳动。
- **引用块**：
    - 渲染态：显示左侧表示引用的竖条，隐藏 Markdown 标记符号 `>`。
    - 编辑态：不显示左侧表示引用的竖条，较弱色显示 Markdown 标记符号 `>`。
- **Callout 块**：
    - 渲染态：显示 Callout 对应样式，隐藏 Markdown 标记。
    - 编辑态：显示完整 Markdown 源码，仅弱色显示 `[!类型]`、折叠标记和行首 `>`，自定义标题与正文保持正常颜色。鼠标从标记行进入编辑，键盘可通过源码边界进入。
- **Setext 标题**：
    - 本条不作用于普通标题样式（ATX 标题）。
    - 渲染方法：第一行的标题内容渲染为对应标题格式，第二行紧接的 Markdown 标记按正文格式（而不是显示方法）渲染。
    - 语法编辑单元：标题内容和下一行紧接的 Markdown 标记两行。
    - 渲染态：显示第一行标题内容和格式，隐藏下一行紧接的 Markdown 标记，但保留空位。
    - 编辑态：显示第一行标题内容和格式，弱显示下一行紧接的 Markdown 标记。
- **图片**：点击图片，或光标位于图片源码范围紧邻的前后边界时，在图片上方显示可编辑的 Markdown 源码，同时保留图片预览。
- **表格**：
    - 能够准确解析和编辑时，始终保持表格形式，直接编辑单元格；不因光标进入而展开整张表格源码。
    - 单元格内的行内语法遵循普通文本的显示规则，表格分隔符等结构标记在源码模式中编辑。
    - 表格的专用交互优先于外层容器的整体源码展开规则，位于 Callout 等容器内时，仍应保留能够准确映射的表格编辑区域。
- **Mermaid 和其他嵌入**：分别规定选中、进入源码编辑和退出编辑的方式，并同时提供鼠标与键盘入口。

## 三、光标与选区

光标和选区必须对应 Markdown 源码中的准确位置，不得仅依赖渲染后的文本位置。

在普通文本编辑区域，选区折叠时，未加修饰键的左右方向键按源码顺序移动，不跳过隐藏的 Markdown 标记。即将进入隐藏标记时，应在同一次操作中显示相关源码并移动光标，不要求额外按键。

表情符号和组合字符按用户感知的完整字符处理，普通移动和删除不得将其异常拆开。非空选区的收起、按词移动等操作遵循平台约定，同时保持准确的源码映射。

鼠标点击渲染文本时，光标应落在最接近点击位置的有效源码边界。选区可以跨越隐藏标记，但实际范围始终以源码为准。

表格采用单元格导航规则：单元格内部按文本移动，边界处按表格规则进入相邻单元格或离开表格，不要求逐个经过隐藏的结构标记。图片等专用渲染区域的选中状态，也必须关联到明确的源码范围。

自动换行后的上下方向键沿屏幕视觉行移动，源码容器和表格单元格内也遵循此规则；到达单元格上下边界后才切换相邻行。导航不得为离开文档末尾的代码块或表格而隐式创建内容。

键盘输入、换行和导航时，滚动应使光标保持在扣除遮挡后的可视区域内。源码与实时模式正文编辑区聚焦时保持无框，以光标和选区提示编辑位置；其他控件仍保留焦点提示。

## 四、内容编辑与剪贴板

### 编辑与撤销

输入、删除、替换和快捷操作必须准确修改对应源码，并作为完整、可撤销的编辑操作提交。操作范围以外的文字、空格、换行和标记写法保持原样。

Enter 延续列表、调整缩进、增删表格行列等辅助编辑，必须有明确的触发条件和修改范围。一次明确的剪切、替换或辅助编辑，应能通过一次撤销完整恢复；连续输入可以按既定规则合并撤销记录。

普通文本 Enter 逐次创建换行；列表或引用中 Enter 延续当前结构，空项再次 Enter 退出。Shift+Enter 写入硬换行或列表续行；Tab／Shift+Tab 以 4 个空格调整列表层级，空列表项也须保持正确层级与标记后的光标位置。

表格使用方向键及 Tab／Shift+Tab 导航，Enter 进入下一行同列；Cmd／Ctrl+Enter 在当前行下方增加空行，Cmd／Ctrl+Shift+Backspace 删除当前数据行并保留表头。行数包含表头，不计 Markdown 分隔行。

修改表格单元格不得顺带对齐整张表格、统一空格或重写分隔符。格式整理应作为明确命令提供。

### 复制与剪切

三种模式的普通复制均以实际选中的源码范围为准；剪切仅适用于可编辑模式。

复制结果必须与该源码范围逐字一致，不得根据渲染效果自动补全或删除标记。例如，对 `# 标题` 只选中 `标题` 时，复制结果为 `标题`；选中包含 `# ` 的完整范围时，结果才是 `# 标题`。

“选择整个块”等专用操作，应明确是否包含格式标记和末尾换行。表格跨单元格复制取两端源码位置间的连续范围，包含中间结构标记；跨单元格剪切先切换源码模式并保留选区，再次剪切才执行删除。不能用普通文本选区准确表达的选择，不得隐含套用普通剪切规则。

剪切必须复制并删除完全相同的源码范围。

代码块的专用“复制代码”按钮复制显示的代码正文并带末尾换行，不包含围栏；普通选区复制仍遵循源码范围。阅读模式无法准确映射选区时，先显示只读源码供重新选择。

### 粘贴

普通文本粘贴应保留收到的原文，不得因当前模式或格式上下文而自动整理、补全或改写 Markdown。

富文本转 Markdown、按表格单元格分配内容、自动转义等转换，应作为明确功能提供，不得成为普通粘贴的隐含行为。

用户输入或粘贴后，若内容不再满足原有语法结构，应按新的源码重新判断显示方式，不得为了维持渲染效果擅自修复内容。

## 五、显示稳定性与异常回退

模式切换、源码显隐、解析、渲染和异步展示刷新本身：

- 不修改正文，不触发内容保存或同步，不创建内容撤销记录。
- 在同一文档未被外部替换的情况下，不清空已有撤销与重做历史。
- 保留准确选区；阅读模式无法显示编辑光标时，保留返回编辑模式所需的位置。
- 尽量保持滚动位置和光标附近的视口稳定。

中文等输入法进行组合输入期间，不得因重渲染、状态切换或回退而丢失文字、重复提交或移动光标。可能中断组合输入的展示切换，应推迟到组合输入结束后执行。

图片等异步内容加载完成时，只能更新展示，不得修改正文或干扰当前编辑。

解析和渲染不得擅自修复 Markdown。无法识别的内容按原文显示；解析边界能够确定的其他部分仍可正常渲染。

无法确定语法归属或准确映射操作时，应在接受该操作前回退到对应源码；局部回退不足以保证正确性时，使用源码模式。不得先修改渲染内容，再猜测如何恢复源码。

回退规则优先于保持表格形式、隐藏标记和减少页面跳动等显示要求。

## 六、参考与验收

本规范未明确的交互细节，可以参考 Obsidian 的实时预览（Live Preview）行为。采用前应记录参考版本、平台和具体行为，补充到本项目的交互说明与验收用例中。

外部参考不得覆盖本规范对源码保真、准确编辑和撤销完整性的要求。

验收应同时检查源码变化与用户交互，覆盖文本导航、嵌套语法、表格和图片、剪贴板、输入法、模式切换及异常回退；不能仅凭渲染结果判断编辑是否正确。

## 七、开发与维护方向

- **本地优先**：输入和本地保存不等待网络，同步在后台完成。
- **职责清晰**：编辑、展示、保存与同步各自负责自己的工作；新增语法和功能遵守本文统一的编辑规则。
- **变更可验证**：修改编辑器时，同时检查源码、操作结果与撤销行为，更新受影响的验收用例，并在变更日志中记录行为变化。
- **原则先行**：不能因实现困难而降低源码保真、准确编辑和撤销完整性的要求；确需修改原则时，先由用户决定。
