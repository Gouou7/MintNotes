# 编辑器架构原则

[返回项目说明](../README.md) · [用户行为](guide.md) · [开发与验证](../README.md#开发与发布)

本文是编辑器的发布门槛，只规定长期架构边界。语法、按键、布局和平台行为写入使用指南并由测试约束。只有用户明确要求修改这些原则时才能编辑本文；需求或实现与其冲突时，应停止并提交架构决策。

## 核心原则

1. **完整保留 Markdown。**未经用户编辑，不得改变源码或把语义等价视为字符串相同。
2. **只有一份权威正文。**编辑、历史、持久化、同步和导出都以规范 Markdown 为准；解析树、DOM 与渲染结果只是派生状态。
3. **所有编辑都是源码事务。**内容变化必须指定准确源码范围、结果选区和原子撤销单元；不得从 DOM 或全文重序列化猜测意图。
4. **本地优先。**输入与本地提交不得等待网络；规范内容进入本地写入路径后才能同步。
5. **扩展能力受控。**扩展只能通过公开契约识别、展示或请求源码事务，不得绕过权威状态与依赖方向。

## 状态与坐标

- **编辑器**提供实时、源码、阅读三种编辑模式；前两者可编辑，阅读模式只读。实时模式内的 `editing`／`rendering` 是语法展示状态，不是额外模式。
- `CanonicalSource` 是控制器接受的规范 Markdown；缓存和快照可以存在，但不能独立演变为当前正文。
- `SourceOffset` 按 JavaScript UTF-16 码元表示规范源码边界；`SourceSelection` 的 `anchor`、`head` 以及所有公开范围都使用这一坐标。
- `SourceTransaction` 是唯一内容提交协议，包含源码编辑、结果选区、来源和必要的派生更新提示。
- 解析结构、源码映射、诊断、装饰、节点视图、输入法缓冲、渲染结果和临时资源均可重建，不得进入正文、内容历史、持久化、同步或导出。
- 解析、渲染、模式／选区变化和异步展示刷新是只读过程，不得修改源码、触发 `onChange` 或创建撤销记录。

临时兼容表示只允许用于外部解析或渲染，且必须可逆、可映射到规范坐标、不持久化。编辑必须先安全映射并提交为源码事务；无法证明映射正确时，在接受输入前回退到规范源码。

## 分层与依赖

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| 应用／保险库 | 提供规范 Markdown；接收提交；管理修订、加密、IndexedDB 和同步。 | 保存编辑器视图、DOM 或派生文档作为正文。 |
| 控制器／核心 | 持有规范源码、选区和撤销历史；解析、映射并原子应用源码事务。 | 暴露原始视图、维护第二份可提交正文或让网络参与本地编辑。 |
| 展示宿主／阅读模式 | 管理装饰、渲染生命周期、失败回退与只读输出。 | 修改源码、写历史或持久化展示结果。 |
| 产品扩展 | 通过核心契约声明匹配、展示或类型化源码命令。 | 直接操作 ProseMirror／DOM，绕过控制器，或被核心反向依赖。 |

依赖方向固定为：**应用组合核心与扩展；扩展依赖核心契约；核心不导入产品扩展。**

## 数据流与重置

```text
规范 Markdown → 控制器 → 解析与映射 → 派生文档 → 展示 → DOM
用户意图 → SourceTransaction → 新规范源码／选区／撤销历史
          → 应用状态 → 本地加密持久化 → 后台同步
异步展示数据 → 展示宿主 → DOM
```

展示、局部更新或重新解析都不能反向改写源码。初始化只建立首个文档世代，不通知内容变化。外部整篇替换必须调用显式重置 API，建立新世代、设置选区并清除或重建撤销历史；不得伪装成用户编辑或通过 `onChange` 回送。

## 源码事务

- 本地事务针对当前 `CanonicalSource` 构造并立即应用；跨异步边界必须携带可验证的文档世代，拒绝过期事务，除非经过明确重映射。
- `edits` 使用事务前坐标，范围有效且互不重叠；插入内容保持原字符串。`selection` 使用事务后规范坐标。
- 事务整体成功或失败；失败不能改变源码、选区或历史。一个明确用户命令对应一个撤销单元。
- 只有确实改变源码的已接受事务才能通知一次内容变化。无变化、展示刷新、派生重建和语法状态切换不通知、不入历史。
- 先提交新源码，再更新派生状态；重新解析不能继续改写源码。
- 输入法可以暂存组合文本，但只有最终源码事务能改变正文。
- ProseMirror 变化必须携带源码事务，或通过能够证明准确的限定映射转换；否则拒绝。DOM 文本、差异启发式和派生文档全文序列化不得用于通用内容恢复。

## 扩展契约

- 声明式展示只能读取声明范围内的源码和有限语义上下文，不接收原始编辑器视图，也不能派发文档事务。
- 修改内容的能力必须返回类型化 `SourceTransaction`；宿主服务的附件、导航、渲染结果和临时 URL 不得写回 Markdown。
- 每种语法保持独立扩展并声明准确源码范围。重叠由明确规则解决；无法唯一归属时拒绝展示，不能依赖注册顺序。
- 异步渲染必须带世代身份并支持取消、清理和过期结果丢弃。失败时回退为用户源码，不能影响规范状态。
- 展示资源默认只在内存中。遗留底层接口只用于迁移；新功能不得采用。

## 变更准入

编辑器更改必须证明：状态归属明确；内容变化形成准确原子事务；派生状态不持久化；依赖方向不变；输入不等待网络；源码效果有针对性测试，用户行为同步到使用指南。

出现以下任一情况即属于架构提案，不能作为普通功能修改继续：

- 引入另一份可独立编辑、提交或持久化的文档模型；
- 从 DOM、渲染结果或派生文档序列化回写 Markdown；
- 绕过 `SourceTransaction`，或暴露原始编辑器视图；
- 让展示状态进入历史、同步、导出或服务器；
- 让输入或本地提交依赖网络；
- 改变本文的层次、依赖方向、事务协议或扩展权限。
