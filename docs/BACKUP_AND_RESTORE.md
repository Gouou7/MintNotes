# 备份和恢复

[文档索引](README.md)

服务器备份会保护账户记录、密钥信封、回收站／历史保留设置、加密头像、可信端点与会话历史、加密对象、同步修订、加密笔记历史快照与名称、历史保护位与随机附件引用关系、清除标记、同步变更、激活记录和加密附件分块。备份不包含笔记、历史名称、历史笔记、头像或附件明文，但它仍属敏感数据，因为会暴露账户、端点、IP、活动、历史时间／类型／保护状态、随机 ID 关系和密文大小等元数据，以及可供离线猜测密码的材料。

备份策略需要同时包含两层：

- **加密服务器备份：**保留账户、同步状态、修订、笔记历史密文和附件密文。
- **明文 Markdown ZIP 导出：**独立于应用保留可移植、可读的笔记和文件夹结构。

请单独保存恢复密钥。仅有任一备份层，都无法同时弥补恢复密钥丢失和密码遗忘。

## 创建一致的在线备份

应用的备份命令使用 SQLite 在线备份 API，在服务接受写入期间也可安全运行：

```bash
docker compose exec notes pnpm backup
```

该命令会创建 `/data/backups/mint-notes-<timestamp>.sqlite`，并输出包含路径和 SHA-256 摘要的 JSON。将指定文件复制出 Docker 卷：

```bash
mkdir -p backups
docker compose cp notes:/data/backups/mint-notes-YYYY-MM-DDTHH-MM-SS-sssZ.sqlite ./backups/
```

使用备份主机可用的 SHA-256 工具，将复制后的文件与命令输出的摘要进行核对。摘要应与备份分开保存。

不要直接复制正在使用的 `notes.sqlite` 文件。数据库使用 WAL 模式，文件级复制可能遗漏仍记录在 WAL 中的已提交事务。

## 保留与存储

以下策略可作为实际起点：

- 保留七份每日备份。
- 保留四份每周备份。
- 保留十二份每月备份。
- 至少在应用服务器和 Docker 卷之外保存一份加密副本。

应根据可接受的数据损失量和可用存储空间调整保留策略。保护备份访问权限，对服务器外介质加密，并定期测试旧备份是否仍可读取。

明文 Markdown ZIP 导出必须存放在独立加密的位置。它们本来就是可读数据，不处于应用端到端加密边界内。

## 恢复演练

始终先在独立部署中测试恢复。只有代表性用户能够解密笔记和附件时，才算恢复成功；仅仅能打开 SQLite 并不够。

1. 选择一份备份并验证其记录的 SHA-256 摘要。
2. 准备一个数据卷为空的全新 Mint Notes 部署。
3. 将备份放入该卷的 `/data/notes.sqlite` 时，保持 `notes` 服务停止。
4. 启动服务，确认 `GET /api/health` 返回 `{"ok":true}`。
5. 测试多个账户的正常登录。
6. 在指定测试账户上测试使用恢复密钥重置密码。
7. 打开有代表性的文件夹和笔记，然后在第二个浏览器上验证修订同步。
   如果浏览器保存的游标比恢复后数据库的游标更新，服务器必须返回重置响应，让客户端从零重放，并通过正常冲突处理保留任何较新的本地发件箱条目。
8. 下载有代表性的附件，验证其可解密，并创建一份新的 Markdown ZIP 导出。
9. 确认管理员仍可创建激活码并查看账户存储量，同时无法看到笔记明文。
10. 打开**设置 > 安全**，确认可信端点历史可读；撤销一个满足 24 小时规则的指定测试端点，并验证其所有会话均停止工作。
11. 确认加密头像在恢复后可以解密；随后只对一次性测试用户执行管理员删除，并确认另一用户的数据仍然可用。
12. 打开一篇代表性笔记的**历史**面板，确认自定义历史名称可以解密；保护一个引用附件的快照，并验证单项删除、清空历史和永久清除笔记／附件都会保留它。然后取消保护，将其恢复为副本，并确认原笔记及其余历史仍保持完整。

历史保护是实时数据库中的保留状态，并非不可变备份策略。恢复旧备份会把保护位、元数据密文、引用、笔记和附件恢复到备份捕获时的准确状态；之后发生的更改无法从该备份恢复。删除账户、删除部署卷或丢弃备份代次仍不受保护机制约束。

如果恢复后的服务报告不受支持或旧版架构，请勿强制打开数据库或编辑 `PRAGMA user_version`。应回到兼容的应用构建，或按[部署指南](DEPLOYMENT.md)所述通过可移植 Markdown 导出恢复。

## 替换生产环境

替换正在运行的生产卷之前：

1. 创建最后一次在线备份并将其复制出来。
2. 停止服务，防止继续写入。
3. 在替换环境通过完整恢复演练前，保留旧卷。
4. 启动替换环境，并监控登录、同步、附件下载和备份创建。

不要仅因服务达到健康 HTTP 状态，就删除恢复前备份或旧卷。
