# 系统设计

[返回项目说明](../README.md)

本文按功能说明 Mint Notes 当前实现的系统结构、数据流、安全保证与已知限制。编辑器交互原则单独成文，在对应章节引用；部署操作见[自托管指南](self-hosting.md)。所有说明应能由代码、测试和配置验证，实现变化时同步更新。

## 总体架构与数据边界

```text
浏览器 / PWA
  React + Markdown 编辑器 + 加密 Worker
  加密 IndexedDB + 持久发件箱
             │ HTTPS 密文
             ▼
单个 Fastify 服务
  静态资源、账户、同步、历史、附件 API
             │
             ▼
SQLite /data（WAL）+ 独立在线备份
```

系统不需要 Redis、对象存储、搜索服务或独立后台 Worker 服务。浏览器负责明文、密钥、本地搜索、目录与编辑器状态；服务器管理认证、用户作用域的不透明对象、修订、变更序列、历史与附件分块。

浏览器端加密保护笔记标题、Markdown、标签、文件夹名称与结构、锁定状态、历史名称与内容、头像，以及附件名称、MIME、密钥和字节。大纲、搜索索引、工作区和编辑器状态只在本地派生或保存。

服务器仍可观察账户身份与角色、随机用户／对象／历史／附件／会话／端点 ID、密文大小、修订和同步时间、历史时间／类型／保护位、保留设置、配额、浏览器摘要、IP 与活动时间，以及受保护历史到随机附件 ID 的关系。端到端加密不隐藏这些元数据。

设计针对数据库或备份泄露、运维人员读取存储、密文篡改或重新绑定、猜测对象 ID 的跨账户访问，以及普通网络故障、覆盖和误删提供保护。它不防御主动篡改前端代码的服务器、恶意浏览器扩展、已解锁设备上的恶意软件或物理访问。各功能的其他限制在下文说明。

## 账户认证与设备访问

### 登录、会话与用户隔离

服务器验证浏览器派生的认证秘密，并仅存储其慢速哈希，不接收主密码或解密密钥。会话与端点使用独立随机 Cookie 值，生产环境设置 `Secure`、`HttpOnly`、`SameSite=Strict`；SQLite 只存这些凭据的哈希。端点标识不能单独认证。

所有用户对象、修订、变更、历史和附件查询都从已认证会话取得 `user_id`，URL、查询和正文不能指定所有者。未知对象与跨用户对象返回不可区分的未找到响应。

密码恢复和账户禁用撤销所有端点；密码更改撤销其他端点。离线设备的远程撤销在下次联网验证时生效。

### 本机解锁与离线访问

已记住设备可以在 IndexedDB 中保存不可导出的 AES-GCM `CryptoKey`、加密的本机解锁凭据和最近验证的用户／端点快照。离线身份快照只允许本地路由；同一端点经 `/api/auth/me` 重新验证前，禁用同步、SSE、远程附件、账户和管理请求。

启用 PIN 后，持久设备信封还由 PIN 派生密钥加密；PIN 派生密钥与明文信封不持久化。标签页刷新使用的加密信封只保存在 `sessionStorage`，锁定、登出和非刷新启动会清除或拒绝它。五次 PIN 失败会删除本地信任并请求撤销端点，但短 PIN 仍可被复制浏览器存储的攻击者离线猜测。

锁定清除已解锁密钥、明文和 Blob URL，保留本地密文与发件箱。登出会删除当前用户的浏览器数据，包括未同步内容和设备凭据；这与普通锁定不同。

## 笔记编辑与本地保存

编辑器属于浏览器端系统，以原始 Markdown 为权威正文。模式、显示、导航、剪贴板、撤销与异常回退的要求由[编辑器架构原则](editor-architecture.md)单独规定。笔记锁只防误操作，不提供额外密码保护或服务器权限隔离。

同一篇笔记的编辑控制器在实时、源码和阅读模式间保持存在，统一管理完整正文（含 Front Matter）、源码选区及撤销／重做。正文只通过带明确替换范围的原子源码事务提交；ProseMirror 负责派生排版与原生输入，不再为产品编辑路径另建历史或运行会重写正文的兼容输入规则。解析器为原文文字、空行和表格单元格提供位置来源，展示更新不通过搜索同名文字或反向序列化 DOM 恢复 Markdown。源码 textarea 的换行规范化只属于显示投影，未编辑范围的 CRLF 等原始换行保持不变。

阅读转换同时传递字符来源，普通复制按选区对应的原文切片；无法证明来源的操作先回退到源码展示。图片 Blob URL 只由附件解析器用于预览，不进入编辑正文或撤销记录。语法显隐、图片异步刷新与模式切换不创建内容事务；组合输入期间延迟展示切换，确认输入后统一提交。

```text
编辑 → 内存 → 浏览器加密 → 原子 IndexedDB 对象 + 发件箱 → 后台条件上传
```

本地写入按用户和对象串行，无关对象可并发。输入与本地保存不等待网络；本地密文和重试条目确认写入后才进入同步流程。刷新、切换笔记、页面隐藏和普通锁定会请求立即保存待提交内容。

IndexedDB `webmd-notes-v2` 保存加密对象、附件分块、历史、修订、游标、发件箱、设备偏好和可选设备凭据。明文文档、搜索索引、解密历史、附件 Blob URL 与已解锁密钥只存在于内存；本机解锁所用的不可导出设备密钥按上一节单独保存。旧 `webmd-*` 命名属于兼容协议，不应无迁移重命名。

## 内容加密与密钥管理

主密码经版本化 Argon2id 参数派生根密钥，再通过 HMAC-SHA-256 将认证与包装用途分离。随机保险库密钥分别由主密码包装密钥和独立恢复密钥保护；附件使用各自随机密钥。主密码、恢复密钥、设备密钥和保险库密钥不以明文发送给服务器。

对象、历史负载、历史元数据和每个附件分块都使用 Web Crypto AES-256-GCM 与全新随机 96 位 nonce。AAD 至少绑定用户、对象身份、类型／领域、版本和修订；附件还绑定分块索引与总数，以防止密文被篡改或移用于其他对象。加密沿用现有 Worker 与 Web Crypto，不新增自制密码学原语或复用 nonce。

## 同步与冲突处理

对象按随机 ID 寻址；服务器为每次接受的变化增加对象修订和用户变更序列。客户端以持久游标拉取，并以 `baseRevision` 和幂等键推送。SSE 只提示新游标，周期拉取提供兜底，因此正确性不依赖长连接或 Service Worker。

拉取页面只有在全部密文通过认证、解密并原子写入本地后才推进游标。无效对象被隔离，不影响其他笔记，也不能覆盖最后一份已知良好副本。并发更新保留服务器版本，并把本地版本及其附件复制为冲突副本；设备时间不决定胜者。

## 历史、回收站与永久清除

历史快照及其元数据使用与笔记相同的本地优先写入和安全重试边界，过期操作不能覆盖较新的本地状态。服务器修订独立保留，用户可见历史删除不删除同步修订。

删除先写墓碑。保留期到期或在线明确确认后才物理清除；立即清除要求已认证会话、明确确认和已同步墓碑。待处理对象、附件、历史或受保护历史会阻止清除。

历史保护防止普通删除、历史清理或相关笔记／附件清除时移除受保护版本，但不抵御账户或卷删除、旧备份恢复和恶意管理员。保留设置及用户操作见[使用指南](guide.md#图片历史与回收站)。

## 附件与导入导出

### 附件保存、同步与读取

每个附件属于一篇笔记，使用随机 UUID、独立密钥和约 1 MiB 分块。复制、冲突或恢复为副本时必须生成新 UUID 与密钥。客户端下载后校验分块身份、顺序、认证标签、明文大小和摘要，再创建短期 Blob URL。

附件必须先原子保存加密分块、清单与发件箱，之后才插入 Markdown 引用。同步顺序为分块、清单、所属笔记，避免笔记引用尚未保存的附件。

客户端按文件签名验证栅格图片，拒绝 SVG；内置客户端单图上限为 25 MiB。服务端大小限制与部署配置见[自托管指南](self-hosting.md#配置与启动)。

### 导入导出与明文边界

导入与导出完全在浏览器处理。ZIP 会规范化路径并拒绝路径穿越和重复项；Markdown ZIP 以 `_attachments/` 相对路径保持可移植性。格式与操作方式见[使用指南](guide.md#导入与导出)。

导出结果是明文，不属于端到端加密保护范围，必须保存到可信或另行加密的位置。

## Web 运行与内容安全

生产环境必须使用 HTTPS、精确的 `APP_ORIGIN` 和严格 CSP。状态更改同时依赖 `SameSite=Strict` Cookie 与 Origin 检查；代理与配置方法见[自托管指南](self-hosting.md#反向代理与日志)。

原始 HTML、可执行嵌入、运行时 CDN 脚本和远程字体禁用。KaTeX 与 Mermaid 从本地包运行；JavaScript `unsafe-eval` 禁用。新增分析、远程来源、原始 HTML 或可执行嵌入前，必须重新审查 CSP 与本文的数据和信任边界。

## 服务端存储、日志与备份

### 数据库与兼容

SQLite schema v2 使用 WAL，保存账户、认证哈希、会话、端点、配额、保留策略、不透明对象与历史、修订、变更、墓碑和附件分块。数据库虽包含密文，仍含敏感元数据和可供离线猜测的材料。

数据库版本、升级与回退限制见[自托管指南](self-hosting.md#恢复与升级)。协议和存储命名的兼容约束见 [AGENTS.md](../AGENTS.md#安全与兼容)。

### 日志与运维责任

应用只向 stdout 写结构化事件，不收集浏览器日志，也不在 SQLite 保存日志。日志不得包含原始 URL／查询、IP、用户名、完整 ID、标头、Cookie、正文、认证或恢复秘密、激活码、密文、nonce、密钥或附件字节。日志保留由部署方管理。

运维方必须保护前端构建、主机、反向代理、`.env`、日志、数据库和备份。备份使用 `server/backup.ts` 提供的 SQLite 在线备份，不能直接复制运行中的数据库；恢复密钥、数据库备份和明文 Markdown 导出需要分别演练恢复。具体流程见[自托管指南](self-hosting.md#备份)。

## 代码组织与职责

- `src/editor/core/`：规范 Markdown、源码事务、解析／映射和受限扩展契约。
- `src/editor/extensions/`：Callout、Comment、Math、Mermaid、WikiLink 等产品扩展。
- `src/crypto/`、`src/storage/`：浏览器加密与 IndexedDB。
- `src/features/vault/`：保险库状态、持久化、同步、历史、附件和视图控制器。
- `server/`：会话派生授权、领域路由、SQLite 仓库、维护与备份。

`src/App.tsx`、`VaultApp.tsx`、`server/index.ts` 和 `server/app.ts` 只负责组合。`VaultWorkspace.tsx` 与 `server/routes.ts` 是待继续提取的协调边界，不是新增领域逻辑的扩展点。
