# 架构概览

[返回项目说明](../README.md)

本文说明 Mint Notes 当前实现采用的系统结构、数据流和职责边界，重点记录理解与维护系统所必需的设计，而不是逐一罗列模块和函数。实现细节有变化时，以代码、测试和配置为准，并同步更新受影响的说明。

## 系统边界

```text
浏览器 / PWA
  React + Markdown 编辑器 + 加密 Worker
  加密 IndexedDB + 持久发件箱
             │ HTTPS 密文
             ▼
单个 Fastify 服务
  静态资源、账户、同步、历史、附件 API
             │
             ▼
SQLite /data（WAL）+ 独立在线备份
```

不需要 Redis、对象存储、搜索服务或独立 Worker。浏览器拥有明文、密钥、本地搜索、目录与编辑器状态；服务器只管理认证、用户作用域的不透明对象、修订、变更序列、历史与附件分块。

## 本地优先写入

```text
编辑 → 内存 → 浏览器加密 → 原子 IndexedDB 对象 + 发件箱 → 后台条件上传
```

本地写入按用户和对象串行，无关对象可并发。输入与本地保存不等待网络；本地密文和重试条目确认写入后才进入同步状态。刷新、切换笔记、页面隐藏和普通锁定会请求立即刷新待保存内容。登出是明确例外：它会删除当前用户的浏览器数据和未同步内容。

附件必须先原子保存加密分块、清单与发件箱，之后才插入 Markdown 引用。同步顺序为分块、清单、所属笔记。历史快照及其元数据使用相同的本地优先和代次安全重试边界。

## 同步与删除

对象按随机 ID 寻址；服务器为每次接受的变化增加对象修订和用户变更序列。客户端以持久游标拉取，并以 `baseRevision` 和幂等键推送。SSE 只提示新游标，周期拉取提供兜底，因此正确性不依赖长连接或 Service Worker。

拉取页面只有在全部密文通过认证、解密并原子写入本地后才推进游标。无效对象被隔离，不影响其他笔记，也不能覆盖最后一份已知良好副本。并发更新保留服务器版本，并把本地版本及其附件复制为冲突副本；设备时间不决定胜者。

删除先写墓碑。保留期到期或在线明确确认后才物理清除；待处理对象、附件、历史或受保护历史会阻止清除。服务器修订独立保留，用户可见历史删除不删除同步修订。

## 存储与会话

IndexedDB `webmd-notes-v2` 保存加密对象、附件分块、历史、修订、游标、发件箱、设备偏好和可选设备凭据。明文文档、搜索索引、解密历史、附件 Blob URL 与密钥只存在于内存。旧 `webmd-*` 命名属于兼容协议，不应无迁移重命名。

已记住设备可以保存不可导出设备密钥和最近验证的用户／端点快照。快照只允许本地路由；服务器重新验证前禁用同步、SSE、远程附件、账户和管理操作。有 PIN 时，持久设备信封再次由 PIN 派生密钥加密，标签页刷新信封只保存在 `sessionStorage`，锁定、登出和非刷新启动会清除或拒绝它。

SQLite schema v2 保存账户、认证哈希、会话、端点、配额、保留策略、不透明对象与历史、修订、变更、墓碑和附件分块。所有用户对象查询都从已认证会话取得 `user_id`；请求输入不能选择所有者。

## 附件与可移植数据

每个附件属于一篇笔记，使用随机 UUID、独立密钥和约 1 MiB 分块。复制、冲突或恢复为副本时必须生成新 UUID 与密钥。客户端下载后校验分块身份、顺序、认证标签、明文大小和摘要，再创建短期 Blob URL。

导入与导出完全在浏览器处理。ZIP 会规范化路径并拒绝路径穿越和重复项；Markdown ZIP 以 `_attachments/` 相对路径保持可移植性。导出结果是明文，不属于端到端加密边界。

## 代码边界

- `src/editor/core/`：规范 Markdown、源码事务、解析／映射和受限扩展契约；详见[编辑器架构原则](editor-architecture.md)。
- `src/editor/extensions/`：Callout、Comment、Math、Mermaid、WikiLink 等产品扩展。
- `src/crypto/`、`src/storage/`：浏览器加密与 IndexedDB。
- `src/features/vault/`：保险库状态、持久化、同步、历史、附件和视图控制器。
- `server/`：会话派生授权、领域路由、SQLite 仓库、维护与备份。

`src/App.tsx`、`VaultApp.tsx`、`server/index.ts` 和 `server/app.ts` 只负责组合。`VaultWorkspace.tsx` 与 `server/routes.ts` 是待继续提取的协调边界，不是新增领域逻辑的扩展点。
