## 总体架构与安全边界

```text
浏览器 / PWA
  React + Markdown 编辑器 + 加密 Worker
  加密 IndexedDB + 持久发件箱
             │ HTTPS 密文
             ▼
单个 Fastify 服务
  静态资源、账户、同步、历史、附件 API
             │
             ▼
SQLite /data（WAL）+ 独立在线备份
```

系统不需要 Redis、对象存储、搜索服务或独立后台 Worker 服务。浏览器负责明文、密钥、本地搜索、目录与编辑器状态；服务器管理认证、用户作用域的不透明对象、修订、变更序列、历史与附件分块。

模块划分、入口组合与协调层的职责约束见 [AGENTS.md](../AGENTS.md#模块边界)。

### 数据与信任边界

浏览器端加密保护笔记标题、Markdown、标签、文件夹名称与结构、锁定状态、历史名称与内容、头像，以及附件名称、MIME、密钥和字节。大纲、搜索索引、工作区和编辑器状态只在本地派生或保存。

服务器仍可观察账户身份与角色、随机用户／对象／历史／附件／会话／端点 ID、密文大小、修订和同步时间、历史时间／类型／保护位、保留设置、配额、浏览器摘要、IP 与活动时间，以及受保护历史到随机附件 ID 的关系。端到端加密不隐藏这些元数据。

设计针对数据库或备份泄露、运维人员读取存储、密文篡改或重新绑定、猜测对象 ID 的跨账户访问，以及普通网络故障、覆盖和误删提供保护。它不防御主动篡改前端代码的服务器、恶意浏览器扩展、已解锁设备上的恶意软件或物理访问。各功能的其他限制在下文说明。

## 账户、设备与密钥

### 登录、会话与用户隔离

服务器验证浏览器派生的认证秘密，并仅存储其慢速哈希，不接收主密码或解密密钥。会话与端点使用独立随机 Cookie 值，生产环境设置 `Secure`、`HttpOnly`、`SameSite=Strict`；SQLite 只存这些凭据的哈希。端点标识不能单独认证。

所有用户对象、修订、变更、历史和附件查询都从已认证会话取得 `user_id`，URL、查询和正文不能指定所有者。未知对象与跨用户对象返回不可区分的未找到响应。

密码恢复和账户禁用撤销所有端点；密码更改撤销其他端点。离线设备的远程撤销在下次联网验证时生效。

### 内容加密与密钥管理

主密码经版本化 Argon2id 参数派生根密钥，再通过 HMAC-SHA-256 将认证与包装用途分离。随机保险库密钥分别由主密码包装密钥和独立恢复密钥保护；附件使用各自随机密钥。主密码、恢复密钥、设备密钥和保险库密钥不以明文发送给服务器。

修改主密码只重新包装保险库密钥，不改变恢复密钥；重置恢复密钥须废止旧密钥。修改用户名需要在线验证主密码，并验证现有恢复凭据或同时生成替代恢复密钥；身份、相关凭据与密钥信封须原子更新，避免失配。

对象、历史负载、历史元数据和每个附件分块都使用 Web Crypto AES-256-GCM 与全新随机 96 位 nonce。AAD 至少绑定用户、对象身份、类型／领域、版本和修订；附件还绑定分块索引与总数，以防止密文被篡改或移用于其他对象。加密沿用现有 Worker 与 Web Crypto，不新增自制密码学原语或复用 nonce。

### 本机解锁与离线访问

已记住设备可以在 IndexedDB 中保存不可导出的 AES-GCM `CryptoKey`、加密的本机解锁凭据和最近验证的用户／端点快照。离线身份快照只允许本地路由；同一端点经 `/api/auth/me` 重新验证前，禁用同步、SSE、远程附件、账户和管理请求。

启用 PIN 后，持久设备信封还由 PIN 派生密钥加密；PIN 派生密钥与明文信封不持久化。标签页刷新使用的加密信封只保存在 `sessionStorage`，锁定、登出和非刷新启动会清除或拒绝它。五次 PIN 失败会删除本地信任并请求撤销端点，但短 PIN 仍可被复制浏览器存储的攻击者离线猜测。

锁定清除已解锁密钥、明文和 Blob URL，保留本地密文与发件箱。登出会删除当前用户的浏览器数据，包括未同步内容和设备凭据；这与普通锁定不同。

## 工作区与界面

### 笔记组织与本地偏好

布局、主题、语言、字号、排序和编辑模式属于当前浏览器的偏好，不作为跨设备同步内容。文件树同级名称不能重复，文件夹不能移入自身或后代。锁定笔记允许查看、移动、复制和导出，但禁止编辑或移入回收站；副本默认解锁。笔记锁只防误操作，不提供额外密码保护或服务器权限隔离。

打开笔记须同步更新文件树的当前条目与范围选择起点；多选与批量操作仍可独立选择多个条目。大纲、字数、搜索结果和文件树等派生结果可延迟更新，但不得阻塞正文输入、本地保存和笔记切换；切换笔记时不得沿用旧笔记的大纲或字数。

### 布局、滚动与焦点

窄屏侧栏作为抽屉显示，收起后其控件不得继续参与键盘焦点导航。工具栏、信息栏的层级低于抽屉、菜单与对话框。

编辑窗格由独立布局组件管理，上下栏覆盖在正文滚动区域上，正文可从其背后经过。历史预览条计入顶部占用高度，不叠加第二层模糊。布局测量仅在尺寸变化时更新遮挡高度，保留桌面／手机栏高、安全区域和正文首尾留白。

三种编辑模式沿用实际滚动容器，光标自动滚动、大纲及脚注跳转使用扣除上下栏后的可见区域。布局及材质变化不改正文、选区或撤销记录。编辑器核心仅通过可选的类型化滚动视口回调取得滚动元素及上下遮挡尺寸，不接收产品布局规则。

### 统一材质与可访问性

磨砂表面用于编辑区上下栏、树与历史上下文菜单、Toast 和登录卡片。颜色、模糊与透明度集中在 `src/styles.css`，新增位置必须复用共享规则。仅使用背景模糊，不添加饱和度、光晕或模糊动画；不以容器 `opacity` 实现材质，保留清晰前景、控件实色状态与各组件圆角、边框和阴影，上下栏不增加浮层阴影。

普通文字（包括小字与次要文字）的前景与合成背景对比度至少为 `4.5:1`，以浅／深色主题叠加黑白及高对比内容检查；次要文字使用共享前景变量，禁用控件保留禁用态表达。不能以增加模糊半径弥补对比度不足。依据见 [WCAG 文字对比度要求](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)。

默认使用不透明背景，仅在浏览器支持时渐进启用背景模糊，并兼容 WebKit。减少透明效果或强制颜色模式下恢复实色表面。不使用 JavaScript 模糊模拟、持续滚动监听、常驻 `will-change`、设备档次检测或独立材质开关；透明度改善可读性，不代表减少模糊计算。

布局和材质验收覆盖浅／深色、桌面／平板／手机、三种编辑模式、历史预览与不同长度笔记，以及 iPhone Safari/PWA 的首屏、软键盘、旋转和安全区域。含图片、Mermaid 的长笔记须对比开启／关闭模糊时的滚动、输入和掉帧情况；浏览器支持不等于性能验收通过，未完成的实机验证必须明确记录。

## 编辑器集成与本地持久化

### 编辑器集成边界

同一篇笔记的编辑控制器跨模式保持存在，管理完整 Markdown（含 Front Matter）、源码选区及撤销历史；正文只通过带明确替换范围的原子源码事务提交。ProseMirror 负责派生排版与原生输入，不另建产品编辑历史，也不通过兼容输入规则或反向序列化 DOM 重写正文。

解析与阅读转换须传递准确的字符来源，不通过搜索同名文字恢复位置。源码 textarea 的换行规范化仅属于显示投影，未编辑范围的 CRLF 等原始换行保持不变。图片 Blob URL 只供附件预览，不进入正文或撤销记录。模式、语法显隐、剪贴板、组合输入及异常回退的具体行为统一遵循[编辑器架构原则](editor-architecture.md)。

### 本地写入与失败处理

```text
编辑 → 内存 → 浏览器加密 → 原子 IndexedDB 对象 + 发件箱 → 后台条件上传
```

本地写入按用户和对象串行，无关对象可并发。输入与本地保存不等待网络；本地密文和重试条目确认写入后才进入同步流程。刷新、切换笔记、页面隐藏和普通锁定会请求立即保存待提交内容。

保存状态必须区分本地持久化和远程同步；离线或上传失败不能被表述为本地保存失败。本地加密或 IndexedDB 写入失败时，必须持续明确警告，不能显示为已保存。

IndexedDB `webmd-notes-v2` 保存加密对象、附件分块、历史、修订、游标、发件箱、设备偏好和可选设备凭据。明文文档、搜索索引、解密历史、附件 Blob URL 与已解锁密钥只存在于内存；本机解锁所用的不可导出设备密钥仅按[设备访问协议](#本机解锁与离线访问)单独保存。兼容命名约束见[数据库与兼容](#数据库与兼容)。

## 同步与冲突

对象按随机 ID 寻址；服务器为每次接受的变化增加对象修订和用户变更序列。客户端以持久游标拉取，并以 `baseRevision` 和幂等键推送。SSE 只提示新游标，周期拉取提供兜底，因此正确性不依赖长连接或 Service Worker。

拉取页面只有在全部密文通过认证、解密并原子写入本地后才推进游标。无效对象被隔离，不影响其他笔记，也不能覆盖最后一份已知良好副本。并发更新保留服务器版本，并把本地版本及其附件复制为冲突副本；设备时间不决定胜者。

## 历史与数据清除

历史快照及其元数据使用与笔记相同的本地优先写入和安全重试边界，过期操作不能覆盖较新的本地状态。服务器修订独立保留，用户可见历史删除不删除同步修订。

以历史版本覆盖当前笔记前，必须创建当前内容的安全检查点；恢复为副本时保留原笔记，并遵循附件复制的身份与密钥隔离要求。

删除先写墓碑。保留期到期或在线明确确认后才物理清除；立即清除要求已认证会话、明确确认和已同步墓碑。待处理对象、附件、历史或受保护历史会阻止清除。

受保护版本仍计入配额，包含受保护历史的永久清除批次必须拒绝。历史保护防止普通删除、历史清理或相关笔记／附件清除时移除受保护版本，但不抵御账户或卷删除、旧备份恢复和恶意管理员。

## 附件与数据迁移

### 附件保存、同步与读取

每个附件属于一篇笔记，使用随机 UUID、独立密钥和约 1 MiB 分块。复制、冲突或恢复为副本时必须生成新 UUID 与密钥。客户端下载后校验分块身份、顺序、认证标签、明文大小和摘要，再创建短期 Blob URL。

附件必须先原子保存加密分块、清单与发件箱，之后才插入 Markdown 引用。同步顺序为分块、清单、所属笔记，避免笔记引用尚未保存的附件。

客户端按文件签名验证栅格图片，拒绝 SVG；内置客户端单图上限为 25 MiB。服务端大小限制与部署配置见[部署指南](deployment.md#生产配置)。

### 导入导出与明文边界

导入与导出完全在浏览器处理，支持 Markdown、文本和 ZIP 导入。ZIP 导入保留目录与空文件夹，规范化路径并拒绝路径穿越和重复项，最多接受 4,000 个文件；相对图片须通过内容校验且符合单图大小限制。

无附件笔记导出为 `.md`，含附件的笔记或文件夹导出为 ZIP；附件写入 `_attachments/`，引用改为相对路径以保持可移植性。附件不完整时必须停止导出，不生成缺失内容的成功结果。

导出结果是明文，不属于端到端加密保护范围，必须保存到可信或另行加密的位置。

## 运行安全与维护

### Web 运行与内容安全

生产环境必须使用 HTTPS 和严格 CSP。`APP_ORIGIN` 默认留空，状态更改按请求协议与 Host（含端口）校验同源，并拒绝缺少 Origin 或非 HTTPS 来源的请求；显式设置时按固定的 HTTPS 源精确匹配。状态更改同时依赖 `SameSite=Strict` Cookie 与 Origin 检查。标准部署开启代理信任，由受控代理限制可接受的域名、保留 Host 并覆盖转发头，后端仅允许受控入口访问；代理与配置方法见[部署指南](deployment.md#反向代理与日志)。

原始 HTML、可执行嵌入、运行时 CDN 脚本和远程字体禁用。KaTeX 与 Mermaid 从本地包运行；JavaScript `unsafe-eval` 禁用。新增分析、远程来源、原始 HTML 或可执行嵌入前，必须重新审查 CSP 与本文的数据和信任边界。

### 数据库与兼容

SQLite schema v2 使用 WAL，保存账户、认证哈希、会话、端点、配额、保留策略、不透明对象与历史、修订、变更、墓碑和附件分块。数据库虽包含密文，仍含敏感元数据和可供离线猜测的材料。

旧 `webmd-*` 存储、Cookie、标头、AAD、附件 URL 与导出标识符属于兼容协议，不得无保留数据的迁移而重命名。数据库版本、升级与回退限制见[部署指南](deployment.md#恢复与升级)。

### 日志与运维责任

应用只向 stdout 写结构化事件，不收集浏览器日志，也不在 SQLite 保存日志。日志不得包含原始 URL／查询、IP、用户名、完整 ID、标头、Cookie、正文、认证或恢复秘密、激活码、密文、nonce、密钥或附件字节。日志保留由部署方管理。

运维方必须保护前端构建、主机、反向代理、`.env`、日志、数据库和备份。备份使用 `server/backup.ts` 提供的 SQLite 在线备份，不能直接复制运行中的数据库；恢复密钥、数据库备份和明文 Markdown 导出需要分别演练恢复。具体流程见[部署指南](deployment.md#备份)。
