# 安全模型

[返回项目说明](../README.md)

本文说明 Mint Notes 当前实现能够提供的安全保证、信任边界和已知限制，而不是尚未落地的目标，也不是漏洞披露政策。安全说明必须能由代码、测试和部署配置验证；实现变化时，应同步检查并更新本文。

## 数据边界

浏览器端加密保护笔记标题、Markdown、标签、文件夹名称与结构、锁定状态、历史名称与内容、头像、附件名称、MIME、密钥和字节。大纲、搜索索引、工作区和编辑器状态只在本地派生或保存。

服务器仍可观察账户身份与角色、随机用户／对象／历史／附件／会话／端点 ID、密文大小、修订和同步时间、历史时间／类型／保护位、保留设置、配额、浏览器摘要、IP 与活动时间，以及受保护历史到随机附件 ID 的关系。端到端加密不隐藏流量元数据。

## 覆盖与不覆盖的威胁

设计覆盖数据库或备份泄露、运维人员读取存储、密文篡改或重新绑定、猜测对象 ID 的跨账户访问，以及普通网络故障、覆盖和误删。

它不防御主动篡改前端代码的服务器、恶意浏览器扩展、已解锁设备上的恶意软件或物理访问。笔记锁只防误操作；历史保护不抵御账户或卷删除、旧备份恢复和恶意管理员。明文导出不受保护。短 PIN 可被复制浏览器存储的攻击者离线猜测。

## 密钥与密文

主密码经版本化 Argon2id 参数派生根密钥，再通过 HMAC-SHA-256 领域分离认证与包装用途。随机保险库密钥分别由主密码包装密钥和独立恢复密钥保护；附件使用各自随机密钥。服务器只接收认证秘密并存储其慢速哈希，不接收密码、恢复密钥、设备密钥或保险库密钥。

对象、历史负载、历史元数据和每个附件分块都使用 Web Crypto AES-256-GCM 与全新随机 96 位 nonce。AAD 至少绑定用户、对象身份、类型／领域、版本和修订；附件还绑定分块索引与总数。不得新增自制密码学原语或复用 nonce。

可选设备密钥为 IndexedDB 中不可导出的 AES-GCM `CryptoKey`。启用 PIN 后，持久设备信封还由 PIN 派生密钥加密；PIN 派生密钥与明文信封不持久化。五次失败删除本地信任并请求撤销端点，但不能作为防离线暴力破解保证。

## Web 与账户安全

- 生产环境必须使用 HTTPS、精确 `APP_ORIGIN` 和严格 CSP。状态更改同时依赖 `SameSite=Strict` Cookie 与 Origin 检查。
- 会话与端点 Cookie 使用独立随机值，并设置 `Secure`、`HttpOnly`、`SameSite=Strict`；SQLite 只存哈希。端点 Cookie 本身不能认证。
- 原始 HTML、可执行嵌入、运行时 CDN 脚本和远程字体禁用。KaTeX 与 Mermaid 从本地包运行；JavaScript `unsafe-eval` 禁用。
- 用户作用域只从认证会话派生。URL、查询和正文不能选择 `user_id`；未知和跨用户对象返回不可区分的未找到响应。
- 密码恢复和账户禁用撤销所有端点；密码更改撤销其他端点。离线设备的远程撤销在下次联网验证时生效。
- 立即清除要求已认证会话、明确确认和已同步墓碑；受保护历史与待处理队列会阻止数据丢失。

## 日志与运维

应用只向 stdout 写结构化事件，不收集浏览器日志，也不在 SQLite 保存日志。日志不得包含原始 URL／查询、IP、用户名、完整 ID、标头、Cookie、正文、认证或恢复秘密、激活码、密文、nonce、密钥或附件字节。日志保留由部署方管理。

运维方必须保护前端构建、主机、反向代理、`.env`、日志、数据库和备份；数据库虽为密文，仍包含敏感元数据和可供离线猜测的材料。应分别演练恢复密钥、SQLite 在线备份和明文 Markdown 导出。新增分析、远程来源、原始 HTML 或可执行嵌入前，必须重新审查 CSP 与本模型。
